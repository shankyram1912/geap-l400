# Agent Spec: bq-agent

## Overview
`bq-agent` is a standalone specialist agent built with the Google Agent Development Kit (ADK) in Python that answers the question: *"Have we seen this software problem before, and how was it fixed?"* It performs semantic search over an internal database of past engineering incidents in BigQuery (`code_assist_bugs.known_bugs`) and returns the most similar incidents with their concrete resolutions.

The agent communicates over Agent2Agent (A2A) protocol as a peer service with no knowledge of any specific caller. It is deployed to GKE behind an external/public LoadBalancer with an application service account `bq-agent-app` granted read-only access to BigQuery.

## Language & Framework
- Language: Python (>=3.11, <3.14)
- Framework: `google-adk` with `a2a-sdk`
- Deployment Target: GKE Autopilot (public LoadBalancer)
- Model: `gemini-3.5-flash` (configurable via `MODEL` env var)
- Embedding Model: `text-embedding-004` (768-dim, Vertex AI `us-central1`)

## Example Use Cases
1. **Startup Failure After Dependency Upgrade**:
   - Input: "FastAPI returns a 500 on startup after a dependency bump."
   - Search: Embed query with `text-embedding-004`, run BigQuery `VECTOR_SEARCH` against `code_assist_bugs.known_bugs`.
   - Output: Cites `BUG-1001` (FastAPI service returns 500 on startup after dependency bump) with cosine distance and resolution (migrating Pydantic v1 config to Pydantic v2 `ConfigDict`).
2. **Unseen / Unrelated Problem**:
   - Input: "How do I make a chocolate cake?"
   - Output: Returns a clear response stating that no similar past incidents were found in the bug database.

## Tools Required
- `find_similar_bugs(query: str) -> str`:
  - Purpose: Retrieve up to 3 most similar incidents from BigQuery using cosine distance vector search.
  - Implementation:
    1. Embed `query` using `genai.Client(vertexai=True, location="us-central1").models.embed_content(model="text-embedding-004", ...)`.
    2. Execute BigQuery `VECTOR_SEARCH` query on table `code_assist_bugs.known_bugs` over column `description_embedding`.
    3. Return structured string containing for each match: `bug_id`, `title`, `description`, `resolution`, and cosine `distance`.
    4. Handle empty results cleanly ("no similar bugs found") and degrade gracefully without throwing if embedding or BigQuery services are temporarily unavailable.

## Constraints & Safety Rules
- **Read-only**: BigQuery operations must be strictly read-only (`SELECT`). Never insert, update, or mutate bug records.
- **Strictly Grounded**: Summarize only what the search returns. Never invent incidents, resolutions, or bug IDs.
- **Citation**: Always cite the `bug_id` for each incident referenced.
- **Graceful Degradation**: On Vertex AI or BigQuery exceptions, return a friendly degradation message instead of raising.
- **Public Reachability**: Exposed on GKE via a public LoadBalancer, advertising the public address in the A2A agent card.

## Success Criteria
- Tool tests pass and accurately retrieve `BUG-1001` for the canonical query.
- Unit and integration tests pass.
- Container builds cleanly and deploys to GKE.
- Public agent card serves single skill with example query.
- End-to-end A2A JSON-RPC query verifies grounded answers with bug citations.
